# Lifeplan: notes for coding agents

Personal life planner (gym first; Languages and Pantry are placeholders). TanStack Start + React 19,
Vite, Tailwind v4 + shadcn/Radix, Supabase (auth, Postgres with RLS), TanStack Query.

## Rules
- Package manager is **npm** (`package-lock.json`). Run `npx tsc --noEmit`, `npm run build` and `npm test` before committing.
- Never print, log or commit secrets. `.env` stays untracked; `.env.example` lists the variables. The service_role key never goes in the repo or in a `VITE_*` variable.
- The database belongs to the owner's own Supabase project. Do not apply SQL yourself. For every schema change add an
  idempotent file to `migrations/` (numbered, with row-level security on every new table) and list it in `MANUAL_STEPS.md`.
  `drizzle/` and `setup.sql` hold the original schema and seed data; do not edit them.
- If something needs the owner (account, key, dashboard paste), write exact steps in `MANUAL_STEPS.md` and keep going.
- If you change existing behavior, say so in `CHANGELOG.md`.
- Style: follow `docs/STYLE.md` (Garden: warm paper, forest ink, green accent #22C55E; light and dark; phone and desktop equal; no extra explanatory text in the UI). Use the tokens in `src/styles.css`, never raw colours. Check new UI at `/design` and with `node scripts/design-shots/shoot.mjs`.
- `src/routeTree.gen.ts` is generated by the router plugin; do not edit it by hand.
- Model calls go through `src/features/gym/ai-provider.server.ts` (provider chosen by `AI_*` env vars). Keys stay server-side.

## Layout
- `src/routes/` file-based routes; `src/features/gym/` data access, AI tools, body map, exercise browser
- `src/integrations/supabase/` client and auth middleware
- `migrations/` new SQL to paste into the Supabase SQL editor
